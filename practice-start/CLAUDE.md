# 대학원생 연구 관리 워크스페이스 — Claude 작업 규칙

이 폴더는 대학원생 한 명이 자기 연구 프로젝트, 주간 기록, 지도교수 미팅, 논문 읽기를 관리하는 워크스페이스다. Claude는 자료 정리와 초안 작성을 돕고, 확정은 사용자가 한다.

학생이 넣고 받아 보는 자료는 Word(.docx), Excel(.xlsx), PowerPoint(.pptx)다. Claude가 프로젝트의 현재 상태를 기억하려고 쌓는 기록(`status.md`, `todo.md` 등)은 텍스트(.md)다.

## 폴더 역할

| 경로 | 역할 | Claude가 할 수 있는 일 |
|---|---|---|
| `inbox/` | 아직 정리하지 않은 자료 (Word, Excel, PPT, 메일, PDF 등) | 읽기, `sources/`로 이동 |
| `sources/<프로젝트>/<접수일>/` | 원본 자료와 출처 기록(`sources.md`) | 읽기, 파일 이동해 오기, `sources.md`에 기록 추가. 자료 파일 내용 수정 금지 |
| `sources/_기타/<접수일>/` | 프로젝트에 속하지 않는 자료(공지, 행정 문서 등) | 사용자 승인 후 이동, `sources.md`에 기록 |
| `projects/<프로젝트>/status.md` | 프로젝트의 현재 상태 (Claude의 기록) | 사용자 승인 후 수정 |
| `projects/<프로젝트>/plan.md` | 연구 질문·마일스톤·위험 | 사용자 승인 후 수정 |
| `projects/<프로젝트>/history/` | 이전 `status.md` 사본 | 추가만. 기존 파일 수정 금지 |
| `weekly/<날짜>.docx` | 나의 주간 기록 (Word) | 초안 작성 |
| `meetings/<날짜>_<종류>/` | 미팅·랩미팅 자료. `brief.docx`(준비), `notes.docx`(내 메모), `summary.docx`(정리), `slides.pptx`(발표) | `brief.docx`, `summary.docx`, `slides.pptx` 작성. `notes.docx`는 사용자 메모 원본이라 수정 금지. 지난 미팅의 `slides.pptx`는 발표한 기록이라 수정 금지 |
| `reading/` | 논문 읽기 노트 (Word) | 작성 |
| `writing/` | 논문·학위논문 초안, figure 후보 | 요청받은 경우에만 수정 |
| `todo.md` | 할 일과 기다리는 일 (Claude의 기록) | 사용자 승인 후 수정 |
| `roadmap.md` | 학위 전체 일정 (Claude의 기록) | 사용자 승인 후 수정 |
| `templates/` | 문서의 제목·표 구조 안내(`.md`) | 요청받은 경우에만 수정 |
| `tools/` | Word·Excel·PPT를 읽고 쓰는 스크립트 | 수정하지 않는다 |

## 반드시 지킬 것

1. **원본을 고치지 않는다.** `inbox/`와 `sources/`의 자료 파일, `meetings/*/notes.docx`는 내용을 수정하지 않는다. 자료는 이동만 하고 `sources.md`에 기록한다. 사용자의 Word, Excel, PPT는 덮어쓰지 말고 새 파일로 만든다.
2. **근거를 붙인다.** 결과나 변화를 말할 때는 근거 파일 경로를 붙인다. 변화는 `기준 날짜 → 현재 날짜` 형식으로 쓴다.
3. **지어내지 않는다.** 파일에 없는 결과, 수치, 결정, 날짜, 피드백을 만들지 않는다. 내용이 없으면 `미입력`, 근거가 약하면 `확인 필요`, 비교할 이전 기록이 없으면 `비교 불가`로 쓴다.
4. **관측과 해석을 나눈다.** "clone 3에서 p53 밴드 없음"(관측)과 "p53 결손 가능성"(해석)을 다른 줄에 쓰고, 해석은 `해석:`으로 시작한다.
5. **이미지 결과를 판정하지 않는다.** 블롯, 겔, 현미경 사진 등은 사용자가 확인해 적은 내용만 쓴다. 이미지만 있으면 `사람 확인 필요`로 표시한다. Word, PPT 안에 들어 있는 그림과 차트도 마찬가지다.
6. **확정 문서는 승인 후 고친다.** `status.md`, `plan.md`, `todo.md`, `roadmap.md`는 바꿀 내용을 먼저 요약해 보여 주고, 사용자가 승인하면 수정한다. `status.md`를 고치기 전에는 현재 파일을 `history/<그 파일의 기준일>_status.md`로 복사한다. 승인받은 변경안에 없는 내용은 넣지 않는다. 변경안을 만들 때는 대상 파일의 실제 칸과 구조를 먼저 확인한다. 승인받은 변경안과 내용이나 위치가 달라져야 하면(없는 칸, 다른 규칙 때문에 더할 내용 등) 고치기 전에 바뀐 변경안을 다시 보여 주고 승인받는다.
7. **읽지 못한 파일은 알린다.** 암호화, 손상, 지원하지 않는 형식(.ab1, .hwp 등)으로 읽지 못했거나 언급만 되고 실제로 없는 파일은 파일명과 이유를 알리고 `확인 필요`로 기록한다.
8. **웹 자료는 출처를 남긴다.** 제목, URL, 발행일(알 수 있을 때), 확인일을 적는다. 검색 결과 요약만으로 사실을 확정하지 않는다.
9. **계산은 방법을 남긴다.** 데이터로 계산한 값(예: ΔΔCt)은 계산 방법과 입력 파일을 함께 적는다.

## Office 파일 다루기

Claude의 Read 도구는 Word, Excel, PPT를 직접 열지 못한다. 이 폴더의 `tools/` 스크립트(Windows PowerShell, 설치할 것 없음)로 읽고 쓴다.

**읽기** — docx, pptx, xlsx를 텍스트로 출력한다. 문서 제목은 `#`, 목록은 `-`, 표는 `| a | b |`, 엑셀 행은 `R<행>: a | b`, 슬라이드는 `=== Slide n ===`와 `[notes]`로 나온다.

```
powershell -NoProfile -ExecutionPolicy Bypass -File tools/office-read.ps1 "<파일 경로>"
```

- 읽는 것은 글자와 표뿐이다. 글꼴·색 같은 서식은 읽지 않는다.
- 그림과 차트는 이름만 나오고 내용은 읽지 못한다. 내용을 짐작하지 않고 `사람 확인 필요`로 쓴다.
- 엑셀은 표시된 값(계산 결과)을 읽는다. 시트가 많거나 길면 `-MaxRows`로 범위를 조정한다.

**Word 만들기** — 내용을 UTF-8 JSON 명세로 쓴 뒤 스크립트로 변환한다. 명세 형식은 `tools/docx-write.ps1` 첫머리의 주석에 있다(제목, 문단, 목록, 표). 한글은 명령줄이 아니라 JSON 파일에 쓴다. 명세와 임시 파일은 워크스페이스 밖의 임시 폴더(`%TEMP%`)에 둔다.

```
powershell -NoProfile -ExecutionPolicy Bypass -File tools/docx-write.ps1 "<명세.json>" "<결과.docx>"
```

- 같은 이름의 파일이 있으면 만들지 않고 멈춘다. 덮어쓰려면 사용자에게 먼저 묻는다(`-Force`).
- 만든 뒤에는 `office-read.ps1`로 다시 읽어 내용이 맞는지 확인하고, 사용자에게 파일을 열어 확인하라고 안내한다.
- 문서의 제목·표 구조는 `templates/`의 양식을 따른다. `#`은 제목, 표는 Word 표로 옮긴다.

**Excel 만들기** — `tools/xlsx-write.ps1`을 같은 방식으로 쓴다. 숫자는 숫자 셀로 들어간다.

**PowerPoint** — `/progress-ppt`의 안내를 따른다(PowerPoint 자동화 또는 python-pptx).

**다른 환경** — 이 스크립트는 Windows용이다. Mac 등에서는 설치된 Word·Excel·PPT용 스킬이나 python-docx, openpyxl, python-pptx로 같은 일을 한다.

## 문서 분량

학생이 읽는 Word 문서는 읽는 데 오래 걸리면 쓰이지 않는다. 주간 기록, 미팅 준비, 미팅 정리는 다음을 지킨다.

- **분량:** 주간 기록과 미팅 준비는 A4 2쪽 이내, 미팅 정리는 1쪽 안팎. `docx-write.ps1`에 `-CountPages`를 붙여 쪽수를 확인하고, 넘으면 줄여서 다시 만든다. 이 실행에서 방금 만든 초안은 `-Force`로 다시 만들 수 있다.
- **한눈에 보기:** 맨 위에 `## 한눈에 보기`를 둔다. 읽는 사람이 1분에 핵심(달라진 것, 막힌 것, 결정이 필요한 것)을 알 수 있게 3~5줄로 쓴다.
- **짧게:** 한 줄에 한 가지만 쓰고, 한 항목은 두 줄을 넘기지 않는다. 프로젝트마다 `바뀐 것`은 5줄, `해석:`은 3줄 이내.
- **근거는 줄이지 않고 옮긴다:** 문장 끝에는 번호만 붙이고(`[1]`), 파일 경로는 문서 맨 끝 `## 근거 파일` 표에 한 번만 적는다(번호, 경로, 비고). 번호가 없는 사실을 쓰지 않는다.
- **표는 필요한 것만:** 이미 끝난 지난 항목은 한 줄("끝난 것: A, B, C")로 묶고, 상태가 바뀌었거나 아직 끝나지 않은 항목만 표에 쓴다. 숫자 표는 한 번만 만들고, 다른 문서에 있는 표는 그 문서를 가리킨다.
- **줄여도 지킬 것:** 규칙 3(지어내지 않기), 4(관측과 해석 나누기), 5(이미지 판정 금지)는 그대로다. `확인 필요`, `사람 확인 필요`, `미입력` 표시와 상태 용어는 빼지 않는다.

## 형식

- 날짜는 `YYYY-MM-DD`. 명령에 날짜가 없으면 오늘 날짜를 쓴다.
- 문서 양식(제목과 표의 구조)은 `templates/`를 따른다.
- 할 일과 피드백의 처리 상태는 `예정`, `진행`, `완료`, `지연`, `소식 없음` 중 하나로 쓴다. 기한 전이고 시작 기록이 없으면 `예정`, 기한이 지났는데 끝나지 않았으면 `지연`, 기한이 없거나 알 수 없는데 기록이 없으면 `소식 없음`이다. 물어봤는데 답이 없으면 `소식 없음 (미입력)`으로 쓴다. `완료`는 `plan.md`의 완료 기준이나 할 일의 내용을 모두 채웠을 때만 쓰고, 기한보다 늦게 끝났으면 `완료 (지연: 기한 YYYY-MM-DD)`처럼 적는다.
- 미팅 폴더 이름은 `<날짜>_<종류>`. 종류는 `교수미팅`, `랩미팅`, `공동연구` 중 하나.
- 답변과 문서는 한국어로 쓴다. 유전자, 시약, 기기 이름 같은 전문 용어는 원어 그대로 둔다.

## 다루지 않는 것

- 공식 연구노트를 대신하지 않는다. 실험 원본 기록은 연구노트에 있고, 여기에는 쪽 번호나 링크만 남긴다.
- FASTQ, 현미경 원본 스택처럼 큰 원시 데이터는 이 폴더에 넣지 않고 `sources.md`에 저장 위치만 적는다.
- 환자 식별 정보 같은 민감 정보는 넣지 않는다. 발견하면 사용자에게 알린다.

## 예시 자료

첫 줄(Word는 첫 문단, Excel은 첫 행, PPT는 표지, 메일은 첫 헤더)에 `예시`라고 적힌 파일과, `sources.md`에서 가상 자료라고 밝힌 파일은 실습용 가상 자료다. 실습 중에는 일반 자료와 똑같이 처리하고, 예시 표시는 지우지 않는다. 새로 만드는 Word 문서의 첫 문단에는 `예시 — 실습용 가상 자료입니다.`를 적는다. 예시 자료는 2026-11-09 ~ 2026-11-17 시나리오다. 자료의 날짜가 오늘보다 늦어도 오류로 보지 말고 그대로 쓴다.
