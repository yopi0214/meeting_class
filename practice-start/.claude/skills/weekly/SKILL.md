# /weekly — 주간 기록

기록 날짜: `$ARGUMENTS` (비어 있으면 오늘 날짜)

## 1. 기준 찾기

- `weekly/`에서 기록 날짜보다 앞선 가장 최근 기록(`.docx`)을 찾아 `tools/office-read.ps1`로 읽는다. 그 날짜가 **기준 날짜**다.
- 이전 기록이 없으면 모든 변화를 `비교 불가`로 표시하고, 현재 상태만 정리한다.
- `inbox/`에 정리하지 않은 파일이 있으면 먼저 알리고 `/intake`를 할지 묻는다.

## 2. 자료 모으기 (기준 날짜 다음 날 ~ 기록 날짜)

- `sources/*/<날짜>/` 중 이 기간에 해당하는 폴더의 파일과 `sources.md`. Excel(.xlsx) 데이터와 Word 문서는 `tools/office-read.ps1`로 읽는다.
- `meetings/` 중 이 기간의 미팅 (`notes.docx`, `summary.docx`)
- 기준이 되는 상태: `projects/*/status.md`, `todo.md`, `roadmap.md`, 기준 날짜의 주간 기록

## 3. 변화 정리

프로젝트마다 다음을 정리한다.

- **바뀐 것:** `기준 날짜 → 기록 날짜` 형식으로 쓰고 근거 파일 경로를 붙인다.
- **관측과 해석:** 다른 줄에 쓰고, 해석은 `해석:`으로 시작한다.
- **계산:** 데이터로 값을 계산했으면(예: ΔΔCt) 계산 방법과 입력 파일을 적는다.
- **반복 실험:** 같은 측정을 여러 번 했으면 결과가 서로 맞는지 확인하고, 다르면 분명히 적는다.
- **지난 피드백과 할 일:** 지난 미팅 피드백과 `todo.md` 항목이 어떻게 됐는지 적는다. 상태는 `CLAUDE.md`의 상태 용어를 쓴다.
- **프로젝트 사이의 연결:** 한 프로젝트의 결과가 다른 프로젝트와 관련 있으면 `해석:`으로 적는다.

## 4. 사용자에게 묻기

파일만으로 알 수 없는 것(막힌 점, 다음 주 계획, 컨디션 등)은 한 번에 짧게 묻는다. 답이 없으면 `미입력`으로 둔다.

## 5. 주간 기록 작성

`templates/weekly.md`의 구조로 Word 문서 `weekly/<기록 날짜>.docx`를 만든다(`CLAUDE.md`의 "Word 만들기"). 첫 문단에 `예시 — 실습용 가상 자료입니다.`를 적는다. 같은 파일이 이미 있으면 덮어쓰지 말고 사용자에게 묻는다. 분량과 구성은 `CLAUDE.md`의 "문서 분량"을 따른다: 한눈에 보기 → 프로젝트별(바뀐 것 5줄 이내) → 지난 피드백·할 일(끝난 것은 한 줄로 묶고, 바뀌었거나 끝나지 않은 것만 표) → 여쭤볼 것 → 기타 → 근거 파일. 숫자 표(예: qPCR 상대량)는 프로젝트당 하나만 두고 계산 방법은 한 줄로 쓴다. 만들 때 `-CountPages`로 쪽수를 확인해 2쪽을 넘으면 줄여서 다시 만든다. 만든 뒤 다시 읽어 확인하고, 사용자에게 Word로 열어 보라고 안내한다.

## 6. 갱신 제안 (승인 후 반영)

- **`projects/<프로젝트>/status.md`:** 바꿀 내용을 요약해 보여 준다. 승인하면 현재 파일을 `history/<현재 파일의 기준일>_status.md`로 복사한 뒤 수정하고, 기준일을 기록 날짜로 바꾼다.
- **`todo.md`:** 상태가 바뀐 항목과 새로 생긴 항목을 보여 주고, 승인하면 반영한다.

## 주의

- 이미지 결과는 `sources.md`의 "사람이 확인한 내용"에 적힌 것만 쓴다.
- 파일 수정 시각만으로 결과가 바뀌었다고 판단하지 않는다.
- 안 된 것, 늦어진 것도 그대로 쓴다.
