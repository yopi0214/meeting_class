# /intake — inbox 자료 정리

`inbox/`의 파일을 하나씩 확인해 `sources/<프로젝트>/<접수일>/`로 옮기고 출처를 기록한다. 파일 내용은 고치지 않는다.

## 순서

1. `inbox/`의 파일 목록과 `projects/`의 프로젝트 목록을 확인한다.
2. 파일마다 내용을 읽고 다음을 정한다. Word, Excel, PPT는 `tools/office-read.ps1`로 읽는다(`CLAUDE.md`의 "Office 파일 다루기"). 메일(.eml)과 텍스트·CSV는 그대로 읽고, PDF는 Read 도구로 읽는다.
   - **프로젝트:** 내용을 `projects/*/status.md`, `plan.md`와 대조해 정한다. 어느 프로젝트에도 속하지 않는 자료는 `_기타`로 분류하고(아래 "주의" 참고), 어느 프로젝트인지 애매하면 옮기지 않고 묻는다.
   - **접수일:** 자료에 받은 날짜(메일 수신일, 파일 이름의 날짜, 문서 안의 날짜 등)가 분명하면 그 날짜, 없으면 오늘 날짜.
   - **종류:** 실험 데이터, 분석 결과, 이미지, 메일, 문서, 논문 등.
   - **읽기 상태:** 읽음 / 일부만 읽음 / 못 읽음(이유).
3. 분류 결과를 표로 보여 준다(파일, 프로젝트, 접수일, 종류, 한 줄 내용, 읽기 상태). 옮기지 않을 파일은 이유를 적는다. 사용자가 승인하면 다음 단계로 간다.
4. 승인된 파일을 `sources/<프로젝트>/<접수일>/`로 옮긴다. 폴더가 없으면 만든다. 복사가 아니라 이동한다.
5. 같은 폴더의 `sources.md`에 파일마다 한 줄을 추가한다. `sources.md`가 없으면 `templates/sources.md`로 만든다.
6. 마지막에 결과를 짧게 알린다: 옮긴 파일, `inbox/`에 남긴 파일과 이유, 확인이 필요한 것.

## 주의

- **이미지**(블롯, 겔, 현미경 등. Word나 PPT 안에 들어 있는 그림 포함)는 내용을 판정하지 않는다. `sources.md`에 `사람 확인 필요`로 적는다. 사용자가 확인한 내용을 말해 주면 "사람이 확인한 내용"에 날짜와 함께 그대로 적는다.
- **언급만 되고 없는 파일**(예: 메일에 "첨부했다"고 적혀 있지만 `inbox/`에 없는 파일)은 "이 폴더 밖에 둔 자료"에 `위치 확인 필요`로 적고 사용자에게 알린다.
- **읽지 못한 파일**(암호화, 손상, 지원하지 않는 형식)은 이유를 적고 `확인 필요`로 둔다.
- 프로젝트에 속하지 않는 자료(공지, 행정 문서 등)는 프로젝트 폴더로 옮기지 않는다. 일정이 들어 있으면 `todo.md`나 `roadmap.md`에 넣을지 묻고, 이어서 `sources/_기타/<접수일>/`로 옮길지 묻는다. 일정의 출처는 옮긴 뒤의 경로로 적는다.
- 결과를 해석하거나 프로젝트 상태를 바꾸지 않는다. 그것은 `/weekly`가 한다.
