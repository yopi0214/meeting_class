# /progress-ppt — 진도점검 PPT

인자: `$ARGUMENTS`

- 첫 단어는 미팅 종류(`교수미팅`, `랩미팅`). 없으면 `교수미팅`.
- 두 번째는 발표 날짜. 없으면 오늘 날짜.
- 결과물: `meetings/<발표 날짜>_<종류>/slides.pptx`

## 0. 도구 확인

- **python-pptx (권장):** Python에서 `import pptx`가 되는지 확인한다.
- **PowerPoint 자동화 (대안):** python-pptx가 없고 Windows에 PowerPoint가 있으면 PowerShell의 PowerPoint COM 자동화를 쓴다. Windows PowerShell 5.1에서는 스크립트 안의 한글이 깨질 수 있으므로, 슬라이드 내용은 UTF-8 JSON 파일로 따로 두고 `Get-Content -Raw -Encoding UTF8`로 읽는다.
- 둘 다 없으면 멈추고 설치 방법(`pip install python-pptx`)을 알려 준다. 사용자 허락 없이 아무것도 설치하지 않는다.
- 작업용 스크립트와 임시 파일은 워크스페이스 밖의 임시 폴더에 둔다.

## 1. 자료 찾기

- **기준 발표:** `meetings/*/slides.pptx` 중 발표 날짜보다 앞선 가장 최근 파일. 없으면 아래 "기본 구성"으로 새로 만들지 묻는다.
- **새 자료 (기준 발표 날짜 다음 날 ~ 발표 날짜):** `weekly/` 주간 기록(`.docx`), `sources/*/<날짜>/`의 파일(Excel 등)과 `sources.md`, 그 사이 미팅의 `summary.docx`. Word, Excel, PPT는 `tools/office-read.ps1`로 읽는다.
- **현재 상태:** `projects/*/status.md`, `todo.md`, `roadmap.md`
- `inbox/`에 정리하지 않은 파일이 있으면 알리고 `/intake`를 먼저 할지 묻는다. 기간 안에 주간 기록이 없으면 `/weekly`를 먼저 할지 묻는다. 주간 기록이 이 PPT의 주 재료다.

## 2. 지난 발표 읽기

`tools/office-read.ps1`로 기준 발표의 슬라이드별 제목, 본문, 표, 발표자 노트를 뽑고, 슬라이드마다 번호, 레이아웃, 제목, 본문 요약, 표·그래프·이미지 여부, 발표자 노트를 목록으로 만든다. 이미지는 위치만 적고 내용을 판정하지 않는다.

## 3. 변경 계획 → 승인

슬라이드마다 처리 방법을 표로 보여 준다.

| 슬라이드 | 처리 | 바뀔 내용 | 근거 |
|---|---|---|---|
| 1 표지 | 수정 | 날짜 | — |
| … | 유지 / 수정 / 추가 / 삭제 | … | `경로` |

**기본 구성** (지난 발표의 순서가 있으면 그 순서를 따른다)

1. 표지: 날짜만 바꾼다.
2. 진도 요약: `기준 날짜 → 이번 날짜`로 바뀐 점 3~5줄
3. 프로젝트별 결과: 새 데이터가 있으면 표나 그래프로 보인다. 바뀌지 않은 결과 슬라이드는 그대로 둔다.
4. 지난 피드백 처리: `CLAUDE.md`의 상태 용어로
5. 다음 계획
6. 여쭤볼 것

사용자가 승인하면 다음 단계로 간다. 승인안과 다르게 만들어야 할 것이 생기면 다시 보여 주고 승인받는다.

## 4. 만들기

- 기준 발표를 `meetings/<발표 날짜>_<종류>/slides.pptx`로 **복사한 뒤** 복사본을 고친다. 기준 발표 파일은 고치지 않는다. 같은 이름의 파일이 이미 있으면 덮어쓰지 말고 묻는다.
- 지난 발표의 양식(슬라이드 마스터, 레이아웃, 글꼴, 색)을 그대로 쓴다. 새 슬라이드는 비슷한 기존 슬라이드와 같은 레이아웃으로 만든다.
- **슬라이드 제목은 관측으로 쓴다.** 검증이 끝나지 않은 결론을 제목에 쓰지 않는다. 예: "clone 3 KO 확인"이 아니라 "clone 3: p53 단백질 소실, 서열 확인 중".
- **안 된 것도 그대로 쓴다.** 반복 실험 결과가 서로 다르거나 실험이 지연됐으면 슬라이드에 적는다.
- **표와 그래프는 근거 파일의 숫자로만 만든다.** 그래프는 PPT 안에서 편집할 수 있는 차트로 넣고, 축 제목과 단위를 단다. 차트를 만들 수 없으면 표로 대신하고 그 사실을 알린다. 계산한 값은 계산 방법을 슬라이드 아래 작은 글씨나 발표자 노트에 적는다.
- **이미지는 사용자가 지정한 파일만 넣는다.** 블롯이나 현미경 사진을 Claude가 고르거나 해석 문구를 붙이지 않는다. 이미지가 서버에만 있으면 빈 상자를 두고 "이미지 넣기: `<저장 위치>`"라고 적는다.
- **발표자 노트**에는 슬라이드마다 근거 파일 경로를 적는다.

## 5. 확인

- 저장한 파일을 `tools/office-read.ps1`로 다시 읽어 슬라이드별 제목과 본문을 뽑고, 3단계 계획과 맞는지 확인한다.
- 슬라이드에 나온 모든 숫자를 근거 파일과 대조한다.
- 가능하면 슬라이드를 그림으로 내보내 글자가 상자를 넘치거나 겹치는 곳이 없는지 본다. 확인하지 못했으면 그렇다고 알린다.
- 마지막에 사용자에게 파일을 열어 확인하라고 안내하고, 빈 이미지 상자와 `확인 필요` 항목을 목록으로 알려 준다.

## 주의

- 결과를 실제보다 좋게 쓰지 않는다.
- 기준 발표 파일과 `sources/`의 자료는 고치지 않는다.
