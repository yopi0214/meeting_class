# /meeting-prep — 미팅 준비

인자: `$ARGUMENTS`

- 첫 단어는 미팅 종류(`교수미팅`, `랩미팅`, `공동연구`). 없으면 `교수미팅`.
- 두 번째는 미팅 날짜. 없으면 오늘 날짜.

## 순서

1. `meetings/`에서 같은 종류의 가장 최근 미팅을 찾는다(**기준 미팅**). 없으면 변화는 `비교 불가`로 표시한다.
2. 기준 미팅 이후의 자료를 읽는다: 기준 미팅의 `summary.docx`(없으면 `notes.docx`), 그 뒤의 `weekly/` 기록, `sources/`, `projects/*/status.md`, `todo.md`, `roadmap.md`. Word, Excel, PPT는 `tools/office-read.ps1`로 읽는다.
3. `meetings/<날짜>_<종류>/brief.docx`를 `templates/meeting-brief.md`의 구조로 만든다(`CLAUDE.md`의 "Word 만들기". 첫 문단에 `예시 — 실습용 가상 자료입니다.`).
   - **분량과 구성:** `CLAUDE.md`의 "문서 분량"을 따라 A4 2쪽 이내로 쓴다. 순서는 한눈에 보기 → 여쭤볼 것 → 달라진 점 → 처리 상태 → 막힌 점 → 다음 계획 → 확인 필요 → 근거 파일이다(미팅 중에 가장 먼저 보는 것이 질문이라 앞에 둔다). 달라진 점은 프로젝트당 4줄 이내로 쓰고, 숫자 표는 주간 기록을 가리키며 다시 만들지 않는다. 만들 때 `-CountPages`로 쪽수를 확인해 2쪽을 넘으면 줄여서 다시 만든다.
   - 지난 미팅 이후 달라진 점 (관측과 해석을 나누고 근거를 붙임)
   - 지난 미팅 피드백과 할 일의 처리 상태 (`CLAUDE.md`의 상태 용어. 파일 기록이나 사용자 확인으로 끝난 것이 분명할 때만 `완료`로 쓰고, 이 준비 자료를 만드는 것 자체로 할 일을 `완료` 처리하지 않는다)
   - 막힌 점과 도움이 필요한 것 (주간 기록·`status.md`에 적힌 것과 사용자가 말한 것만. Claude가 짐작한 위험은 `해석:`으로 시작)
   - 여쭤볼 것과 결정이 필요한 것 (우선순위 순)
   - 다음 계획
4. 같은 폴더에 `notes.docx`가 없으면 `templates/meeting-notes.md`의 구조로 빈 메모 파일(제목, 참석, 빈 목록)을 만들어 둔다.
5. 랩미팅이면 `brief.docx`에 "발표 구성안"(장마다 제목, 핵심 메시지 한 줄, 넣을 그림·표와 그 원본 경로)도 넣는다. 실제 PPT 파일이 필요하면 `/progress-ppt`를 안내한다.
6. 다 만든 뒤 근거가 약하거나 빠진 항목을 따로 알려 준다.

## 주의

- 결과를 실제보다 좋게 쓰지 않는다. 안 된 것, 늦어진 것도 그대로 쓴다.
- 해석과 추측을 사실처럼 쓰지 않는다. 서열 확인 같은 검증이 끝나지 않은 결론은 `확인 필요`로 둔다.
- 기존 `notes.docx`는 고치지 않는다.
